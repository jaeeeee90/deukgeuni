# 득근이 운동방 생성·관리 설계

## 목적
사용자가 모바일 화면에서 운동방을 만들고 관리하며, 기존 날짜별 운동 기록 기능을 새 방에도 그대로 사용할 수 있게 한다.

## 목표
- 이름, 설명, 운동 아이콘을 입력해 현재 사용자가 생성자·첫 회원인 방을 만든다.
- 사용자 생성 방을 예시 방보다 먼저 목록에 표시하고 새로고침 후에도 유지한다.
- 생성자만 이름·설명·아이콘을 수정하거나 방을 삭제한다.
- 방 삭제 시 그 방의 운동 종목·세트·참여 상태만 함께 삭제한다.

## 제외 범위
Supabase, 로그인, 초대, QR, 실시간 동기화, 통계, 외부 이미지 업로드는 구현하지 않는다.

## 설계 결정
- 예시 방은 `src/data/rooms.js`의 정적 데이터로 보존한다.
- 사용자 생성 방은 `deukgeuni:custom-rooms:v1` localStorage 키에 별도로 저장한다. 기존 운동 기록 키 `deukgeuni:workout-demo:v1`은 변경하지 않는다.
- 사용자 생성 방은 `{ id, name, description, symbol, color, creatorId, members, exercises }` 형태로 저장한다. `members`에는 생성자의 안정 ID와 이름이 한 명 들어간다.
- 방 ID는 브라우저 난수 UUID를 우선 사용하고, 사용할 수 없을 때 시간·난수 조합으로 생성한다.
- 홈 목록은 사용자 생성 방을 먼저, 예시 방을 뒤에 붙인다. 같은 이름은 허용한다.
- 상세 화면은 기존 `WorkoutRoomPage`를 재사용한다. 선택한 방은 ID로 유지해 방 정보 수정 후에도 최신 데이터를 표시한다.
- 방 관리는 `creatorId === currentUserId`일 때만 화면에 노출하고, 데이터 함수도 같은 검사를 수행한다.
- 삭제 시 운동 기록 상태에서 해당 `roomId`의 운동 항목, 그 항목의 세트, 그리고 해당 방의 참여 상태만 제거한다.

## UX
- 이름은 앞뒤 공백을 제거한 뒤 1~30자로 검증한다. 설명은 최대 100자다.
- 아이콘은 기존 파스텔 카드와 어울리는 6개 선택지 중 하나를 고른다.
- 방 만들기와 저장에는 코랄 버튼을 사용한다. 삭제는 확인 대화상자에서만 확정한다.
- 작은 화면에서 입력 요소와 아이콘 선택지가 가로로 넘치지 않는다.

## 호환성과 제한
- 기존 운동 기록은 키·버전을 유지해 보존한다.
- 사용자 생성 방 저장 데이터가 손상됐거나 지원하지 않는 버전이면 사용자 생성 방만 빈 목록으로 복구한다. 예시 방과 기존 운동 기록은 영향을 받지 않는다.
- localStorage 기반 데이터는 현재 브라우저 전용의 테스트 데이터다.
